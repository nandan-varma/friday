# CLAUDE.md

Friday: a Next.js 16 (App Router, Turbopack) calendar app with Google Calendar sync and an AI chat assistant.

## Commands
- Dev server: `pnpm dev` (must run on port 3000 — see Testing below)
- Build: `pnpm build`
- Typecheck: `npx tsc --noEmit` (no dedicated script)
- Lint: `pnpm lint` / format: `pnpm format` (check-only: `pnpm format:check`) / both: `pnpm check` — Biome, not ESLint/Prettier
- Unit + integration tests: `pnpm test` (single file: `npx tsx --experimental-test-module-mocks --test path/to/file.test.ts` — see gotcha below)
- E2e tests: `pnpm test:e2e` (Playwright, starts/reuses a dev server on :3000)
- Clean-checkout smoke test: `pnpm test:smoke` (clones current HEAD into `/tmp`, installs, typechecks, lints, builds, tests — only sees committed state)
- DB: `pnpm db:generate` / `pnpm db:migrate` / `pnpm db:studio` (Drizzle)

Required env vars (`.env.local`, not committed): `AUTH_SECRET`, `NEXT_PUBLIC_APP_URL`, `DATABASE_URL` (Neon Postgres), `GOOGLE_CREDENTIALS` (JSON), `OPENAI_API_KEY`. `UPSTASH_REDIS_TCP_URL` is optional — rate limiting and resumable chat streams degrade gracefully (fail open / disabled) without it.

## Architecture
- Route groups: `app/(app)` = authenticated pages + API routes, `app/(auth)` = sign-in/up pages + Better Auth's catch-all route, `app/(compliance)` = static legal pages. Access control for `(app)` happens in `proxy.ts`, not per-page.
- **`proxy.ts` is Next 16's replacement for `middleware.ts`** — the exported function is named `proxy`, not `middleware`. Don't go looking for a `middleware.ts`.
- OAuth tokens live in Better Auth's own `account` table (`db/schema/auth.ts`), encrypted via `encryptOAuthTokens`. App-specific state (which calendars are synced) is a separate `calendar_preference` table.
- The AI chat agent (`agents/chat-agent.ts`, tools in `tools/calendar-tools.ts`, prompt in `prompts/system-prompts.ts`) is a `ToolLoopAgent` from the `ai` SDK; `app/(app)/api/chat/route.ts` persists history via `lib/chat-store.ts` and streams through `lib/resumable-stream-context.ts` (Redis-backed, optional).
- `lib/logger.ts`'s `createLogger` is currently a no-op stub — all levels are silent. Don't assume `log.debug`/`log.info` calls anywhere in the codebase actually print anything.

## Testing conventions
- Unit/integration tests use Node's built-in `node:test` (not Jest/Vitest), run through `tsx`. `pnpm test`'s `--experimental-test-module-mocks` flag is required for `mock.module` to work.
- To isolate a route/module from the database or external APIs, mock the *leaf* dependency (`@/lib/auth`, `@/lib/integrations/google/google-calendar`, `@/lib/redis`, `@/lib/ratelimit`, `@/agents/chat-agent`) rather than `@/lib/api` itself — that keeps real code like `parseJsonBody` under test instead of reimplementing it in the mock.
- `mock.module()` must be called before the module under test is first imported anywhere in that file/process — re-registering a mock after an earlier unmocked import is silently ineffective (stale binding). The established pattern: register one mock per dependency at module scope using a mutable outer-scope variable, dynamically `import()` the module under test once in a `before()` hook, then mutate the variable per test instead of re-mocking.
- Explicit single-file test runs break on paths containing brackets (e.g. `app/(app)/api/chat/[id]/stream/route.test.ts`) — the runner treats the CLI argument as a glob and `[id]` doesn't match itself. Run the full `pnpm test` glob, or a narrower glob, instead.
- Playwright e2e (`e2e/`) runs against the **real dev Neon database** pointed to by `DATABASE_URL`, not a mock or a separate test DB — it signs up throwaway `e2e-*@friday-test.local` users and `e2e/global-teardown.ts` deletes them afterward. The config pins the dev server to port 3000 because Better Auth validates the request origin against `NEXT_PUBLIC_APP_URL`.
- Zod v4 gotcha (bit us in `app/(app)/api/events/route.ts`): `.extend()` throws on a schema built with `.superRefine()`/`.refine()` — use `.safeExtend()` instead. `.merge()` doesn't throw but silently drops a `.refine()` from the merged-in schema, so a refinement composed via `.merge()` needs re-checking manually where it's used.

Code style (imports, component patterns, naming) is documented separately in `AGENTS.md` — everything between its `BEGIN:nextjs-agent-rules`/`END` markers is auto-regenerated by `next dev`, so don't hand-edit that block.
